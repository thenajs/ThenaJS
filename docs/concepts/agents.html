Agentes

Um agente é a menor unidade: uma classe com @Agent. A lógica fica no .agent.ts e o prompt no .agent.md irmão — o framework une os dois.

Anatomia

explorer.agent.ts
@Agent({
  provider: LocalOllamaProvider,   // quem fala com o modelo
  tools: [ShellTool],              // ações disponíveis
  prompt: "./explorer.agent.md",   // obrigatório
})
export class ExplorerAgent {}

Por que o prompt fica no markdown

Prompt é conteúdo, não código. Mantê-lo no .md deixa versionar, revisar e editar o comportamento sem recompilar nada — e mantém o .ts só com a lógica. O caminho é resolvido em relação ao arquivo do agente (também aceita caminho absoluto ou new URL(..., import.meta.url)).

O fluxo padrão

Sem escrever nenhum método, ao executar o agente o runtime:

  • monta as mensagens: system (o prompt do .md) + a projeção do estado;
  • chama provider.chat({ tools, messages });
  • se o modelo pede uma tool, ela é executada e o resultado volta;
  • anexa os turnos ao history e devolve a resposta.

Quando precisar de lógica própria

Use os hooks (interceptar pontos do fluxo) ou o método run(input, ctx) como escape hatch — aí você controla tudo (várias chamadas ao provider, loop de tool-use, gravar campos no ctx para um loop ler, etc.).

Gere o esqueleto com npx mimir g agent <nome> — cria o .agent.ts e o .agent.md já ligados.
