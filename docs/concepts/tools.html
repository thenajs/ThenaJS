Tools

Uma tool é uma ação que o modelo pode chamar. É uma classe @Tool com um schema Zod; a lógica fica em execute(input).

read-file.tool.ts
@Tool({
  name: "read_file",
  description: "Lê o conteúdo de um arquivo.",
  schema: z.object({ path: z.string() }),
})
export class ReadFileTool {
  async execute({ path }: { path: string }) {
    return readFile(path, "utf8");
  }
}

O schema é a fronteira de confiança

O schema (Zod) valida os argumentos que o modelo produziu antes de chamar o execute. É a fronteira entre a saída (não confiável) do modelo e o seu código — mantenha-o estrito.

Onde a tool executa

Quando o modelo decide chamar uma tool, o engine encontra a tool pelo name, valida os args com o schema, executa e devolve o resultado como um turno tool na conversa. Você não escreve if no agente — o provider cuida disso.

Injeção de dependência

O construtor da tool pode receber o WorkflowRuntime — assim uma tool pode disparar outro workflow:

deploy.tool.ts
@Tool({ name: "deploy", description: "...", schema: z.object({ repository: z.string() }) })
export class DeployTool {
  constructor(private readonly runtime: WorkflowRuntime) {}
  async execute(input: { repository: string }) {
    return this.runtime.run(DeployWorkflow, { input });
  }
}

Controlando a execução com hooks

No agente que usa a tool, beforeTool pode alterar os args ou dar throw para cancelar (guardrails), e afterTool pode transformar o output. Veja Hooks. O pacote @thenajs/tools já traz a ShellTool pronta.
