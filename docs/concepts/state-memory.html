Estado & memória

O StateManager guarda o estado da execução e é compartilhado por todos os passos de um workflow. Ele tem três "baldes".

BaldeO que éVira…
historya conversa: turnos user/assistant/toolas mensagens da conversa
memorycontexto durável (ex.: userId, fatos)uma mensagem system
tasksitens sendo acompanhadosnota no system

Como o contexto do modelo é montado

Antes de cada chamada, o agente monta as mensagens: o system do seu prompt (.md) + a projeção do estado (state.toMessages()), que junta memory/tasks num system e adiciona o history. Ou seja, o modelo vê o prompt do agente e a conversa acumulada.

semeando o estado
await app.run({
  input: { message: "Olá" },              // vira o turno 'user' inicial
  memory: { userId: "123", plano: "pro" },   // contexto durável (system)
});

Por que isso importa

Como os turnos vão para o history, os agentes de um workflow se encadeiam pela conversa: o PlannerAgent responde, o ReviewerAgent já vê essa resposta. E como agentes podem gravar campos próprios no ctx (ex.: ctx.reviewApproved), o until de um loop consegue decidir quando parar.
