Arquitetura

O ThenaJs é dividido em três camadas: um engine de execução, uma camada de DX (decorators + runtime) por cima, e o seu app.

camadas
seu app (src/)            agents · tools · providers · workflows · config · main
     │  usa
     ▼
@thenajs/core   (DX)        @Agent · @Tool · @Workflow · hooks · bootstrap · report
     │  usa
     ▼
@thenajs/agentflow (engine) Pipeline · Providers · StateManager · tools · markdown

@thenajs/agentflow — o engine

Faz o trabalho pesado e não conhece decorators. Expõe o Pipeline (com parallel/loop), o StateManager (estado da conversa), os Providers (Ollama/OpenAI) e o tipo ToolType. É baseado em mensagens: o provider recebe messages e devolve um turno.

@thenajs/core — a camada de DX

É o que você importa. Transforma classes decoradas em execução: o @Agent carrega o prompt, o @Tool vira uma ToolType, o @Workflow monta os passos, e o runtime (bootstrapWorkflow/runWorkflow) roda tudo sobre o engine — chamando os hooks e, opcionalmente, gerando o report.

Seu app — src/

Onde você escreve agentes, tools, providers e workflows por convenção. O framework é uma dependência; você só declara as peças.

O caminho de uma execução

fluxo
bootstrapWorkflow(WF, config)
  → runWorkflow  →  Pipeline com os steps do @Workflow
       para cada agente:
         monta messages = [system (prompt do .md), ...estado]
         provider.chat({ tools, messages })  →  { assistant, tool? }
         anexa os turnos ao history  →  alimenta o próximo passo
Como o provider é baseado em mensagens e os turnos vão para o history, os agentes de um workflow conversam entre si pelo estado — não por variáveis soltas. Veja Estado & memória.
