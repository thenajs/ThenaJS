ThenaJs

Um framework para construir agentes de IA de forma declarativa: decorators, prompts em markdown, workflows compostos, hooks e report de execução.

Começar → Ver no GitHub

Comece em segundos

Instale o CLI, crie um projeto e rode — já pronto para editar.

terminal 
npm install -g @thenajs/cli   # instala o CLI
thena create my-agent          # cria o projeto
cd my-agent
npm install
npm start                      # roda o assistente

E um agente é assim — a lógica no .ts, o prompt no .md:

explorer.agent.ts 
import { Agent } from "@thenajs/core";
import { ShellTool } from "@thenajs/tools";
import { LocalOllamaProvider } from "../../providers/ollama.provider.js";

@Agent({
  provider: LocalOllamaProvider,
  tools: [ShellTool],
  prompt: "./explorer.agent.md", // o prompt vive no markdown
})
export class ExplorerAgent {}

Por que ThenaJs

A lógica no .ts, o prompt no .md, e o framework une os dois.

🧩

Decorators

@Agent, @Tool e @Workflow — declarativo: cada peça em seu lugar.

📝

Prompt em markdown

O .agent.md ao lado do .agent.ts é carregado automaticamente. Sem prompt hardcoded.

🔀

Workflows compostos

Orquestre agentes com parallel([...]) e loop({...}), aninhados à vontade.

🪝

Hooks opcionais

beforePrompt, beforeTool, afterTool, afterResponse, onError — intercepte o fluxo.

🛠️

Tools com Zod

Uma tool é uma classe @Tool com schema Zod; pode até disparar outro workflow via DI.

📊

Report de execução

Com report: true, gera um HTML estilo Playwright da run — árvore, decisões e I/O.

Como funciona

Uma camada de DX sobre o engine @thenajs/agentflow (pipeline, providers, estado, tools).

arquitetura
@Workflow  →  orquestra os agentes (sequência / parallel / loop)
   └─ @Agent    →  lógica no .ts + prompt no .md
        └─ provider.chat  →  chama o modelo (Ollama / OpenAI)
             └─ @Tool     →  executa a ação (schema Zod)
